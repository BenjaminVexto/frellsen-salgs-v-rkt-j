
- Målepunkter, portefølje og bonus læser salg fra sales_kunde_maaned/company_mp_info, som holdes ajour af triggere på sales_monthly og companies — så tallene er hurtige og aldrig skal genberegnes manuelt.
- Portefølje-svar sendes gzip+base64 via src/lib/komprimer-json.ts, fordi TanStack Start begrænser poster og bytes pr. svar.
- Sælgertilskrivning sker pr. lokation (locations.saelger_user_id, sat af Aktør-importen via aktoer_anvend_saelgere på serveren); companies.assigned_to er kun hovedkontoens ansvarlige sælger — because one company can have locations with several sellers.
- DB/DG visibility is decided by the database function maa_se_db (admin or profiles.maa_se_db), never by the admin role alone — so it can be switched off per person.
- Address search and group (parent/sister) data come live from the CVR Elasticsearch distribution (produktionsenhed/virksomhed indexes) merged with cvr_penheder — because our local copy only covers CVRs already in the CRM.
- P-enheder link to locations via location_pnr_link (unique per P-nr+location); auto-link only on exact addr_n_vej/addr_n_husnr+zip and skips ambiguous ones; near matches (±4) are only suggested by SQL penhed_koblingsforslag (rejections in penhed_forslag_afvist); kilde 'indirekte' (dealer, via penhed_saet_indirekte/penhed_fjern_indirekte, also manages the forsynes_af relation) counts as covered everywhere — because uncertain matches must never be linked and dealer-supplied sites must not become leads.

- Aktiviteters dato vises og sorteres på activities.udfoert_at (brugervalgt, højst 14 dage tilbage, valideret af trigger); created_at er den uændrede registreringstid — so the two can be compared.
- Maskiners "Placering i bygningen" ligger i maskine_placering pr. serienr. (ikke på location_equipment_units, som importen sletter/genindsætter); importen må kun skrive via import_maskine_placering, der ignorerer tomme værdier og aldrig overskriver CRM-indtastninger — because brugerindtastninger ikke må gå tabt ved import.
- Fakturajournalens DB 0-linjer udledes pr. kunde mod Vismas summeringslinje (src/lib/invoice-db-udledning.ts, invoice_lines.db_kilde, invoice_db_afstemning) — never a general 'DB 0 = 100 %' rule, because real DB-0 sales (machines) exist.
- Salgskort lives as an admin-only tab (?fane=salgskort) in Min salgsstatistik (src/components/salgskort/salgskort-fane.tsx); /admin/salgskort only redirects there — because the map belongs with the sales statistics.
- Distriktsscenarier (distrikt_scenarie, scenarie_distrikt, scenarie_flade, scenarie_saelger) are edited only in Salgskort → Simulering; the current map (distrikter/distrikt_flade) changes only via scenarie_gor_gaeldende, which first archives the old map as a scenario — so the current map can always be restored.
- Simulation assignment rules (scenarie_regel) are evaluated client-side in src/lib/simulering-regler.ts (Frellsen → locked KAM → assign rules → geography → exclude rules) — so the order is tested in one place.
- KAM-aftaler (kam_aftale/scenarie_kam) match on separate kpg1/kpg2/kpg3 lists (OR) plus optional omraade; kodetype/koder are deprecated, and scenarie_gor_gaeldende creates/updates/deletes kam_aftale from the scenario — so a scenario fully describes the KAM setup.
- Telemarketing (role `telemarketing`) is locked out in the DB: every public table gets a RESTRICTIVE policy `tm_spaerret` USING/WITH CHECK (NOT (SELECT er_telemarketing())) — except contact_lists, contact_list_assignments, kontaktliste_ringer, kontaktliste_opkald. NEW TABLES MUST GET THIS POLICY. All server functions use `kraevIntern` middleware (src/lib/kraev-intern.ts), never bare requireSupabaseAuth; views must be security_invoker; the PostgREST pre-request `tm_pre_request` only lets telemarketing call the tm_* RPCs (add new agency RPCs to its allowlist). Agency data flows only through tm_virksomheder/tm_registrer_opkald/tm_gem_kontakt, which require a kontaktliste_ringer row — so a forgotten policy cannot leak sales data.
- CVR-emnesøgning filtrerer ansatte/telefon/postnr i ES (src/lib/cvr-bulk-query.ts, nyeste måned→kvartal→år) og pager med search_after på cvrNummer; 'findes i CRM' afgøres kun af cvr_match_crm (sikre: CVR, moder-CVR, P-enhed, adresse+navn, adresse+telefon, telefon+navn; kun adresse/telefon = "mulig kunde"; adresse/telefon kun mod CRM-virksomheder uden CVR) — because ~40 % of CRM companies have no CVR.
- Any read that can exceed 1,000 rows must page with `.range()` via `hentAlle` (src/lib/hent-alle.ts), and postcode → district seller is resolved only in SQL (`_distrikt_saelger` and its wrappers) — because PostgREST silently caps responses at 1,000 rows.
- CVR director/owner contacts ("Direktør (CVR)") are created only for CVR-imported nyt_emne companies via src/lib/cvr-direktoer.ts, run as `cvr_direktoer_job` batches — so existing customers' contacts are never touched.
- Contact-list status comes only from the latest outcome via SQL `registrer_udfald` (all roles; logs to kontaktliste_opkald); free notes are udfald 'note' and never change status or count as calls; labels/stats in src/lib/telemarketing.ts — so status and statistics cannot drift apart.
